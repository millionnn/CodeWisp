## 概述

V1.2 将 CodeWisp 从「文本搜索 + 文件操作」升级为具备 **代码语义感知** 的 Coding Agent。  
CodeWisp 作为 **LSP Client / Adapter**，不自研 Language Server；LSP 是增强能力，不可用时 Agent 继续用 search/read/run_command。

## Architecture

```text
AgentLoop
    ↓
LSP Tools (read-only, ALLOW)
    ↓
LSPService
    ↓
LanguageServerManager (reuse client per workspace)
    ↓
LanguageServerClient (Fake | PyrightCli | Unavailable)
    ↓
ContextManager ← LSPContextProvider (metadata-first)
```

**边界：**

- AgentLoop **不含** LSP 特判 / 硬编码 edit→diagnostics 循环
- LSP **不修改** 文件、不执行 shell、不 git commit
- 与 Git / Snapshot **正交**
- 不新增 LSP 数据库表

## LSP Tools

| Tool | Permission | 说明 |
|------|------------|------|
| `lsp_diagnostics` | ALLOW | 文件/工作区诊断 |
| `lsp_definition` | ALLOW | 跳转定义（0-based） |
| `lsp_references` | ALLOW | 查找引用 |
| `lsp_symbols` | ALLOW | 文档符号树 |
| `lsp_hover` | ALLOW | Hover 信息 |

不可用时返回结构化 `lsp_unavailable`，Agent 继续。

## Python / Pyright

- **不自动安装**语言服务器
- 检测 PATH 上的 `pyright` / `pyright-langserver`
- 真实 diagnostics：`pyright --outputjson`（`PyrightCliClient`）
- symbols：Pyright CLI 场景下用轻量 AST 补充；definition/references/hover 在无完整 LSP 协议时返回空结果（不崩溃）
- 测试全部使用 `FakeLanguageServerClient`，**不依赖**本机 Pyright

### 配置说明（用户环境）

```bash
# 推荐（npm）
npm install -g pyright

# 或
pipx install pyright
```

确认：

```bash
which pyright
pyright --version
```

然后在目标仓库：

```bash
codewisp -w /path/to/project
/lsp status
```

## Context Integration

`LSPContextProvider` 注入：

- Language / Server / Status
- Diagnostics 摘要（counts + 少量条目）
- Active file symbols（focus path）
- Tip：按需调用 definition/references/…

完整诊断列表与符号树 **不**默认塞进 Context。

## Limitations

- 完整 JSON-RPC Language Server 协议未实现；Python 以 Pyright CLI diagnostics + AST symbols 为主
- TS/Java/Rust：检测 + 接口预留，Adapter 未完整实现
- 无 Web UI / MCP / RepairEngine
- definition/references/hover 在仅 CLI Pyright 时可能为空
