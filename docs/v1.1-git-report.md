## Architecture

```text
AgentLoop
    ↓
Git Tools (git_status / git_diff / git_log / git_branch / git_commit)
    ↓
GitService
    ↓
GitPolicy (read-only ALLOW; commit ASK; destructive DENY)
    ↓
GitRepository (subprocess, shell=False, cwd=repo_root)
    ↓
Local .git

ContextManager
    ↓
GitContextProvider (metadata: branch / counts / changed files / recent commits)
    ↓
Workspace Context（不含完整 diff）
```

**边界原则：**

- AgentLoop **不含** Git 特判
- GitService **不知** AgentLoop / CLI / SQLite
- GitPolicy **不执行**命令
- Snapshot/Revert **不替代** Git；Git commit **不替代** Snapshot

## Git Tools

| Tool | Permission | 说明 |
|------|------------|------|
| `git_status` | ALLOW | 仓库状态摘要 |
| `git_diff` | ALLOW | working tree / staged / 单文件 diff |
| `git_log` | ALLOW | 最近 N 条 commit |
| `git_branch` | list=ALLOW; create/switch=ASK | 分支操作 |
| `git_commit` | ASK + CommitPreview | 仅用户明确要求时使用 |

Tool description 明确告知模型：`git_commit` 不是普通 write tool。

---

## Permission Semantics

**GitPolicy（结构化解析 subcommand + flags）：**

| 级别 | 示例 |
|------|------|
| ALLOW | status, diff, log, show, branch, rev-parse |
| ASK | add, commit, checkout, push, reset, clean, merge, rebase |
| DENY | push --force, reset --hard, clean -fd, branch -D, checkout -- . |

复用 V0.8 `PermissionHandler`：`git_commit` 生成 CommitPreview → ASK → ALLOW/DENY。

---

## Context Integration

`GitContextProvider.build_workspace_context()` 输出：

- Git repository / root
- Branch / ahead / behind
- Working tree counts（modified / staged / untracked）
- Changed files（路径列表，无 patch）
- Recent commits（最近 5 条 one-liner）

**Git metadata first, diff on demand** — Agent 需细节时调用 `git_diff` / `read_file`。

## API

| Method | Path | 说明 |
|--------|------|------|
| GET | `/api/sessions/{sid}/git/status` | 状态 |
| GET | `/api/sessions/{sid}/git/diff` | diff（?path & staged） |
| GET | `/api/sessions/{sid}/git/log` | log（?limit） |
| GET | `/api/sessions/{sid}/git/branches` | 分支 |
| POST | `/api/sessions/{sid}/git/commit` | commit（需 confirm=true） |

HTTP → AgentService → GitService → GitRepository（不经 route 直连 subprocess）。

## Manual Demo（验收场景）

**Phase 1 — Coding task（不自动 commit）：**

```text
git_status → read/search → edit → pytest → git_diff → final answer
```

**Phase 2 — 用户明确要求 commit：**

```text
git_status → git_diff → CommitPreview → Permission → git_commit → git_status (clean)
```

在任意 Git 初始化的小型 Python 项目（含 calculator + pytest）上可复现。

## Limitations

- 无 `git_show` tool（可 V1.2 加）
- 无 Web UI / WebSocket
- 无 Git 专用 DB 表（Git 即持久化）
- `run_command git ...` 仍可用，但结构化 Git workflow 应优先专用 Tools
- CLI `/git` 输出简洁，未接入 Rich diff renderer
